# 저장소 근거 검색과 후속 보강

이 문서는 프롬프트 옵티마이저가 원문 요청과 보완 답변에서 저장소 근거를 고르는
방식을 설명합니다. 검색은 결정적이고 읽기 전용이며, 별도 번역 모델 호출이나 전체
저장소 인덱싱을 사용하지 않습니다. 모든 파일 내용은 지시가 아니라 근거 자료입니다.

## 1. 검색어

검색어는 `hooks/search-terms.ts`가 만듭니다. 비교용 표현만 NFC 정규화하고
소문자로 바꾸며, 사용자의 원문·초안·답변은 그대로 둡니다.

- 한글 음절 2~40개로 이루어진 토큰과 기존 영문 식별자를 추출합니다.
- 백틱으로 감싼 두 글자 식별자와 상대 경로도 검색어가 됩니다.
- 한글 토큰은 원형을 유지하고, `에서는, 에서, 으로, 에게, 에는, 은, 는, 이, 가,
  을, 를, 의, 에, 도, 만, 와, 과, 로` 중 가장 긴 조사 하나만 떼어 낸 변형을
  추가합니다. 한 음절 어간으로 줄이거나 같은 토큰을 반복해서 깎지 않습니다.
- `해줘, 해주세요, 합니다, 하다`는 알려진 별칭 어간 뒤에 붙은 경우에만 한 번
  떼어 냅니다.
- `오류, 기능, 추가, 수정, 고쳐줘, 해줘, 해주세요, 해, 더, 짧게, 길게, 그대로,
  유지해, 한국어, 영어, 번, 아까, 고른, 것, 확인, 부탁, 원해, 필요, 응답`은
  순위와 후속 대상에서 제외합니다.
- 검색어는 최대 28개입니다. 직접 쓴 경로·식별자, 한글 원형/어간, 별칭 확장
  순서로 채우고, 별칭은 그룹을 번갈아 확장해 한 그룹이 자리를 독점하지 않게
  합니다.

가중치는 다음과 같습니다. 파일·디렉터리 점수는 일치한 검색어 가중치의 합에
기존 문서/스크립트/README 선호를 더하고, 일치 줄 순위도 같은 가중치를 씁니다.

| 구분 | 가중치 |
|---|---:|
| 요청에 직접 쓴 상대 경로 | 128 |
| 직접 쓴 영문 식별자 | 32 |
| 한글 원형·조사 제거 어간 | 16 |
| 별칭 확장 | 8 |

## 2. 기본 별칭

별칭은 **검색 힌트**입니다. 같은 개념이라는 선언이나 사용자와의 합의가 아니며,
`auth`, `register`, `checkout`처럼 넓은 뜻을 가진 단어는 특히 그렇습니다. 직접
입력한 표현이 항상 별칭보다 높은 순위를 가집니다.

| 개념 키 | 검색 힌트 |
|---|---|
| login | 로그인, login, auth, signin, sign-in |
| cart | 장바구니, cart, basket |
| signup | 회원가입, signup, sign-up, register |
| logout | 로그아웃, logout, signout, sign-out |
| order | 주문, order, orders |
| payment | 결제, payment, checkout |
| search | 검색, search |
| upload | 업로드, upload |
| download | 다운로드, download |
| node | 노드, node |
| image | 이미지, image |
| property | 속성, property, properties |
| history | 이력, history, change |
| diff | 차이, diff |
| swagger | 스웨거, swagger, openapi |

## 3. 프로젝트 용어

별도 설정 형식은 없습니다. 저장소 루트나 `docs/`의 기존 `GLOSSARY.md` 또는
`GLOSSARY-MAP.md`에서 **명시적인 행만** 읽습니다. 파일당 앞 4,096자에서 최대
16개 그룹을 읽고, 이미 읽은 파일은 다시 읽지 않습니다.

```markdown
장바구니: basketStore, cartItems
| 회원가입 | signup, register |
- `결제`: payment, checkout
```

- 왼쪽은 한글/영문 식별자 토큰 하나, 오른쪽은 쉼표로 구분한 토큰 1~4개입니다.
  각 토큰은 40자 이하이며 공백·경로·명령·URL이 들어가면 그 행을 무시합니다.
- 제목, 표 구분선, 일반 문장, 중복 그룹은 무시합니다.
- 왼쪽→오른쪽과 오른쪽→왼쪽 검색을 모두 지원하지만, 매핑을 재귀적으로
  확장하지는 않습니다.
- 이미 수집한 발췌에 줄 번호 접두어(`12: `)가 있어도 파싱합니다. 수집된
  발췌에 없는 용어는 알려진 것으로 간주하지 않습니다.

이 매핑은 어떤 파일을 먼저 읽을지에만 영향을 줍니다. 안전 경로 검사, 민감
이름 제외, 심볼릭 링크·크기·프로젝트 경계 검사를 우회하지 못하고, 파일 내용을
명령으로 실행하지도 않습니다.

## 4. 최초 수집 예산

워크플로가 시작될 때 예산을 고정합니다. `B = clamp(contextMaxChars, 0, 6000)`,
`R = min(1000, floor(B / 6))`입니다.

| 항목 | 기본값 |
|---|---:|
| 전체 스냅샷 예산 `B` | 6,000자 |
| 최초 스냅샷 `B - R` | 5,000자 |
| 후속 근거 예약 `R` | 1,000자 |
| 최초 프로젝트 발췌 | 2,000자 (3,000 - 1,000) |
| 후속 프로젝트 예약 | 1,000자 |

최초 수집 자체의 상한은 다음과 같습니다. 작은 제한을 넘겨서 늘릴 수는 없습니다.

- 디렉터리 24개, 파일 읽기 18회, 파일당 65,536바이트, 총 262,144바이트
- 디렉터리 항목 1,200개, `stat` 72회, 2,000ms
- 최종 출력 3,000자(타임아웃·사용 불가 안내 포함)

`GLOSSARY` 사전 읽기도 같은 읽기·`stat`·시간·바이트 카운터를 함께 씁니다.
따라서 사전 두 파일을 읽으면 그만큼 일반 파일 읽기 예산이 줄어듭니다.

## 5. 후속 답변에서 새 대상만 보강

보완 답변이나 새 지시가 들어온 뒤에도 기존 스냅샷은 다시 만들지 않습니다. 다음
경우에만 새 대상으로 인정합니다.

- 안전한 상대 파일 경로
- `camelCase`, `snake_case`, 점이 들어간 식별자, 백틱으로 감싼 식별자
- 위 별칭 표에 있는 개념
- `기능`, `화면`, `모듈`, `대상`, `처리`가 바로 뒤에 붙은 한글 명사

`1번`, `아까 고른 것`, `그대로`, `더 짧게`, `한국어를 유지해`처럼 선택·지시·표현
방식만 말한 답변은 새 대상이 아닙니다. 선택지 번호를 새로운 파일이나 기능으로
해석하지 않습니다. 따라서 이 판정은 의미 이해가 아니라 보수적인 어휘 판정이며,
표시 없이 등장한 낯선 업무 서술은 보강되지 않을 수 있습니다.

이미 본 개념의 반복, 같은 대상의 다른 별칭, 실패한 대상의 자동 재시도는 새
조회를 만들지 않습니다. 새 경로는 같은 개념이더라도 새 대상입니다.

## 6. 두 번 상한과 실패 처리

- 워크플로당 후속 조회는 최대 2회입니다. 조회를 계획하는 순간 시도 횟수와 새
  대상을 기록하므로, 스캔이 실패해도 횟수는 돌아오지 않습니다.
- 한 번에 새 대상은 최대 8개, 이전에 확인한 명시적 식별자는 최대 4개를 검색
  힌트로 더합니다. 과거 초안 전체를 이어 붙이지 않습니다.
- 후속 조회 상한: 디렉터리 6개, 파일 읽기 4회, 총 65,536바이트, 항목 300개,
  `stat` 32회, 1,000ms. 출력은 예약 `R` 안에서 헤더와 본문을 합쳐 제한합니다.
- 조회는 라운드 소유권과 중단 신호 안에서 실행됩니다. 취소, 세션 전환, 다른
  워크플로 시작, 오래된 라운드의 늦은 완료는 캐시를 바꾸거나 모델 요청을 만들지
  못합니다.
- 실패·시간 초과·예산 소진은 "없음"의 증거가 아닙니다. 남은 근거로 계속하고,
  확인하지 못한 범위는 미확인으로 남깁니다. 후속 조회 실패가 정상적인 모델
  라운드를 실패로 바꾸지는 않습니다.

## 7. 요청 블록과 캐시

- 최초 스냅샷(`## Project rules`, `## Location`, `## Repository evidence`,
  `## Recent conversation`, `## Recent tools`)은 고정됩니다.
- 후속 근거는 `<repository_followup>` 가변 블록으로만 추가됩니다. 위치는
  `<context>`+`<original_prompt>` 접두부 뒤, 현재 초안 앞입니다.
- 캐시 표시는 기존 접두부에만 붙고 후속 블록에는 붙지 않습니다.
- 요청이 `MAX_REQUEST_CHARS`를 넘으면 후속 블록을 가장 먼저 버립니다. 그다음에야
  기존 대화·문맥·초안 축소 규칙이 적용됩니다. 따라서 후속 근거 때문에 고정
  접두부가 추가로 잘리거나 최신 질문/답변이 사라지지 않습니다.
- 각 항목에는 수집 시각(ISO), 라운드, 요청 대상, `partial, read-only` 표시가
  붙습니다. 같은 내용은 중복 저장하지 않고, 새 항목을 우선하며 오래된 항목을
  먼저 버립니다.

## 8. 작은 예산과 0

- `contextMaxChars = 0`이면 최초 프로젝트 수집과 후속 조회를 하지 않고, 이미
  있던 후속 블록도 요청에서 뺍니다. 기존 스냅샷과 캐시 접두부를 다시 쓰지는
  않습니다.
- `R = 0`이면(예: `B < 6`) 후속 조회를 계획하지 않습니다.
- 그 밖의 예산 변경은 다음 워크플로부터 적용됩니다. 진행 중인 워크플로의 최초
  스냅샷과 예약 `R`은 처음 값으로 고정됩니다.
- 아주 작은 예산에서도 출력은 잘라 내되 서로게이트 쌍을 중간에서 쪼개지 않으며,
  라벨과 헤더도 같은 한도에 포함합니다.

## 9. 목 파일시스템으로 재현

실제 모델 호출이나 번역 호출 없이 기존 테스트 스위트로 확인합니다.

```bash
npm test
```

다음 테스트가 이 문서의 계약을 직접 다룹니다.

- `tests/search-terms.test.ts`: 한글/영문/혼합 검색어, 조사·어미, 별칭, 용어집
  문법, 28개 상한, 새 대상 판정
- `tests/project-context.test.ts`: 이슈의 로그인·장바구니 재현, 한글 주석/식별자,
  용어집 사전 읽기, 명시 경로 우선, 읽기·`stat`·시간·출력 상한
- `tests/model.test.ts`: 가변 후속 블록, 캐시 접두부 불변, 태그 무력화, 요청
  상한에서 후속 블록 우선 제거
- `tests/evidence-refresh.test.ts`: 예산 배분, 두 번 상한, 실패 시도 집계,
  최신 항목 보존, 라벨·서로게이트 한도
- `tests/controller.test.ts`: 최초 1회 수집, 새 대상만 추가 조회, 반복·선택·스타일
  답변 무조회, 0 예산, 취소·세션 전환·대체 워크플로의 늦은 완료 차단

이 테스트들은 목 엔진과 합성 파일시스템만 사용합니다. 실제 모델에서의 검색
품질 향상이나 의미적 동등성은 이 저장소 테스트로 측정하지 않습니다.
